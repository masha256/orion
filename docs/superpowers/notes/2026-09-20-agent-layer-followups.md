## How the execution went, in one paragraph

The plan's code was generated from a tested prototype and verified by extraction, so every implementer applied it byte for byte (each task was diffed against the prototype) and no task needed a fix for a transcription error. Every defect found was a defect in the DESIGN that the plan's own tests had pinned as correct, and the reviews found one in ten of the thirteen tasks: a transcript that could be rewritten; a cited quote that could be spliced from unrelated parts of a page (four rounds to get right); an agent commit that could silently retire a row the user entered; prototype pollution through a config path from model output; a move guard that compounded from run to run; a loop that lost its usage when a tool threw; an approve that applied edits to the agent's own limits with the user's authority. The final review, on the most capable model and pointed at cross-task interactions, then found what no task review could: `runAgent` never reloaded the config, so the mid-run conflict the ledger test pinned could not happen in a real run (the same class of bug as sub-project 2's fake clock); deferred transactions that lose a race instantly whatever the busy timeout; per-request web limits mistaken for per-run ones; and model-written text flowing unbounded into a second agent that has a shell.

### During the tasks

- Task 1: Ruling: reviewer finding (plan-mandated, Critical + Important, one root cause) - finishAgentRun upserts agent_transcripts (`ON CONFLICT DO UPDATE`) and updates agent_runs with no guard, so a second finish silently rewrites a finished run's outcome, usage, and transcript, while the plan's own prose and spec 11.1 say agent_transcripts is append-only. Decided: the spec wins. A run is finished exactly once: finishAgentRun throws OrionError `agent_run_already_finished` when a transcript row already exists, and inserts the transcript with a plain INSERT. The test is "a transcript exists", not "outcome is running", on purpose: abandonStaleRuns marks a run `error/abandoned` without a transcript, and if that process was in fact alive and finishes later, its one finish must still land and record what really happened - cost if wrong: a caller that legitimately needs to re-finish a run (none exists; runAgent finishes once) would get an error instead of an overwrite.
- Task 3: Ruling: reviewer finding (plan-mandated, Important) - persona `temperament` and `sectors` default to '' and [] instead of being required; spec section 9 names defaults only for `model` and `effort`. Decided: the code stands. Both fields are descriptive metadata with no effect on any behaviour (nothing reads them but `persona list/show`), the spec lists them without saying required, and Task 10's config-hash test deliberately loads a persona with only `name`. What the reviewer is right about is that no test pins the choice, so a test-only fix round adds one, plus the missing skill unknown-key test; the spec gets a clarifying line in section 17 at the end - cost if wrong: a persona file missing `sectors` loads instead of failing; one zod line to change.
- Task 4: Ruling: reviewer finding (plan-mandated, Important) - verifyCitation flattens the whole page to one string, so a quote SPLICED from two unrelated blocks (adjacent table cells, paragraphs, a nav item abutting article text) is a contiguous substring and verifies, although the page never says it. The spec's wording ("stripped of HTML tags ... whitespace-normalized") mandates the flattening, but the spec's purpose for the check (5.5, 16: it catches invented citations) is the authority, and a spliced quote is an invented one. Decided: fix. A quote must occur inside ONE block of the page: the page is cut at block-level HTML tags (p, div, td, th, tr, li, br, h1-h6, table, lists, sections, ...) and, for plain text, at blank lines; each block is normalized; inline tags still become spaces, so a quote across <b> still verifies. A quote found only in the flattened page is refused `quote_spans_blocks`, telling the agent to quote within one paragraph, cell, or list item. Spec section 17 gets an item at the end - cost if wrong: a legitimate quote that crosses a <br> or two list items is refused, and the agent must quote a shorter span.
- Task 4: Ruling: both round-1 re-review findings are consequences of my own ruled fix, not implementer slips. A single line break is ambiguous (a wrapped sentence, or the next table row). Decided: (1) in HTML, source newlines are whitespace and only tags break lines; `br` is a SOFT break, not a block tag; (2) a soft break (a <br>, or a single newline in plain text) continues the block only when the next line starts with a lower-case letter; anything else starts a new block. This errs toward refusal on purpose: a false refusal costs the agent one retry with a shorter quote, a false accept lets an invented claim into the data - cost if wrong: quotes that wrap before a capital, a digit, or a `$` are refused until the agent quotes one line; and a plain-text table whose rows start in lower case can still be spliced (accepted residual, recorded for the final review).
- Task 4: Ruling: round-2 finding is again a flaw in my ruled design. Decided: (1) blank lines are HARD breaks in both modes: split on them BEFORE any HTML handling, so a wrong HTML guess can never merge paragraphs (a blank line inside an HTML <p> then causes only a false refusal); (2) LOOKS_LIKE_HTML requires a KNOWN HTML tag name, not any `<letters>` - cost if wrong: on a plain-text page that really contains a known tag name in angle brackets (say `Map<a, b>`), single newlines are read as spaces, so single-newline rows on that page could splice; blank-line paragraphs never can.
- Task 4: Ruling: three rounds of findings share one structural cause: enumerating BLOCK tags means every tag left off the list is a splice route. Decided: invert it. In a page that looks like HTML, EVERY tag is a block boundary unless it is on a short list of known INLINE tags (a, b, i, em, strong, span, code, sup, sub, ...); <br> stays a soft break. LOOKS_LIKE_HTML lists every common structural and inline tag name. Unknown and custom elements therefore err toward refusal - cost if wrong: an inline tag missing from the inline list splits a sentence and causes a false refusal (recoverable: the agent quotes a shorter span). Accepted residuals stand: a page with no known HTML tag at all is read as plain text; plain-text rows that begin in lower case can splice.
- Task 6: Ruling: reviewer finding (plan-mandated, Important) - insertObservation lets a provisional insert supersede any active provisional row at the same (metric, observed_at), so an agent commit could silently retire a row the USER entered, with no trace in the summary.
